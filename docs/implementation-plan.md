# Mocktoon operation contract

Outcome: a standalone FlyEnv plugin and public editable Mockoon JSON examples. Users can install a pinned CLI, copy examples, edit their JSON, select ports/scenarios, run several enabled mocks in one owned CLI process and inspect request history. Original examples and project copies remain independent across updates. No host source changes, licensing changes, new Pinia store, shared configuration or constraint exceptions.

State owners: the mounted page owns form drafts, tab/selection and filters. A module-local reactiveBind singleton owns saved settings (StorageGetAsync/StorageSetAsync), profile catalog, immutable request snapshots, IPC callbacks, progress, errors, operation guards and notices across page re-entry. Fork owns files, CLI bootstrap, processes, PIDs, readiness and shutdown. Renderer flags never prove process liveness.

Runtime install: explicit user action selects an existing FlyEnv Node installation. The fork locates its npm-cli.js using platform-specific layouts, runs npm ci against a bundled lockfile in a unique staging directory with scripts disabled, verifies the CLI version, then atomically renames the successful runtime. Code 200 progress is non-terminal; 0/1 closes listeners. Duplicate installs share one operation. Failure never replaces an existing runtime; only owned staging is removed after its child exits. No global package installs, privilege prompts or automatic retries. npm child has a bounded lifetime and disconnect/exit cleanup.

Lifecycle: ModuleInstalledItem.start/stop/restart owns service operations. The aside registers startExtParam to load saved settings and snapshot enabled profile IDs, ports, scenarios and selected Node. One installed CLI version is one managed service; multiple enabled profiles run together as one process. serviceStartSpawn and Base own PID registration and shutdown. The plugin only adds readiness checks; readiness failure stops its own started process and reports cleanup failure independently. CLI binds every environment to 127.0.0.1, disables proxying, TLS and the admin API, uses bounded request bodies and plugin-owned transaction logs. Stop/disable/update/quit preserve profiles and runtime data. Service startup uses argv arrays and does not depend on a platform shell.

Examples and editing: create uses a request UUID as an idempotency key and exclusive writes. Profile IDs are validated before deriving paths. Save validates the Mockoon environment and atomically replaces only that profile. Editable source configs are separate from launch snapshots. Initial scopes exclude proxy/callback/file-backed responses; templates remain freely editable as ordinary JSON outside the plugin. Required write failures propagate. Profile creation/save results survive supplementary list-refresh errors. Independently invalid profile candidates report their own reason while valid profiles remain usable.

History: read only a bounded log tail, parse independent JSON lines, redact known sensitive headers, retain raw request/response payload text. No request replay or external forwarding in v0.1. History failure affects only history; it cannot negate a successful start or write. Logs are local and may contain submitted bodies; README describes retention and explicit clearing while stopped.

Verification: pinned real CLI validates and serves every example. Exercise successful/rejected/slow/unauthorised/rate-limited/unavailable responses and custom edits; verify source examples unchanged. Test duplicate operations, progress and terminal cleanup, timeout/failure/retry, page re-entry, supplementary refresh failure, invalid candidate isolation, save/ID validation, occupied-port startup, exact argv with spaces, Windows/macOS/Linux npm layouts, process cleanup and request-body capture. Build/import the plugin through the host builder and inspect its archive for examples, host bridges and absence of private host patches or credentials. Actual OS runtime testing is Windows; Unix layouts and platform branches receive focused tests.
